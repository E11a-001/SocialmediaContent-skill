# 跨平台内容原则

这份文件只回答一个问题：什么样的观点值得进入三平台改写。

## 先过 6 个判断

### 1. 这是不是一个明确判断

优先处理这种句子：

- “不要把 X 当成 Y”
- “多数人搞错的是……”
- “真正影响结果的不是 A，是 B”
- “这个平台适合做什么，不适合做什么”

少处理这种句子：

- “内容很重要”
- “我最近有点感悟”
- “真正厉害的人都知道”

如果一句话不能形成明确判断，就先别改平台。

### 2. 核心词有没有定义

凡是出现这些词，都要警惕：

- 高质量
- 影响力
- 精准
- 长期主义
- 个人 IP
- 价值
- 高认知
- 红利

如果用户说不清这些词在这句话里具体指什么，就先拆，不直接写。

### 3. 有没有“值得看”的点

优先选择至少满足一项的内容：

- 有反常识
- 有现实利益相关
- 有具体场景
- 有冲突
- 有代价
- 有具体方法

没有这些抓手的内容，很容易写成平均化废话。

### 4. 有没有证据抓手

跨平台母稿至少要有一种抓手：

- 个人经历
- 用户案例
- 数据
- 具体观察
- 对标案例
- 反例

完全没有抓手，就只能先写判断骨架，不能装作论证已经完成。

### 5. 能不能走完“点击 -> 认同 -> 信任”

至少问自己：

- 别人为什么会点
- 别人为什么会觉得你说得对
- 别人为什么会愿意继续看你

如果只能解决第一步，这只是钩子，不是内容。

### 6. 这句话配不配被长写

博客版默认是最完整的一版。如果一句话根本撑不起一篇文章，就别硬拉长。

适合长写的特征：

- 能拆出至少 3 个层次
- 有反方或误解可处理
- 有案例可展开
- 有行动建议可落地

## 母稿推荐结构

如果观点成立，优先按这个骨架搭：

1. 结论先行
2. 为什么大多数人会搞错
3. 真正该看的变量是什么
4. 一个例子
5. 一个反例或边界
6. 给读者的动作建议

## 常见问题

### 只有情绪，没有判断

处理方式：

- 先把情绪翻译成判断
- 再把判断翻译成场景

### 只有结论，没有过程

处理方式：

- 追问“为什么”
- 追问“反过来为什么不成立”
- 追问“你拿什么证明”

### 只有观点，没有用户

处理方式：

- 明确这句话最该讲给谁听
- 明确他在什么情境下最容易被打中

## 你要保住的东西

做平台内容不是为了变成模板写手。真正该保住的是：

- 判断力
- 具体性
- 语言习惯
- 你反对什么
- 你愿意承担什么立场代价
